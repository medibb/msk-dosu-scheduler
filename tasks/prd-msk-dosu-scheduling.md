# PRD: 근골격계 도수치료 스케줄링 웹앱

## 1. Introduction / Overview (개요)

도수치료사들이 현재 엑셀(`림프 도수치료 2026.xlsx`)과 Notion에 흩어져 관리하는
**근골격계(MSK) 도수치료 환자 스케줄**을 하나의 웹앱으로 통합한다.

현재 문제점:
- 처방 명단은 엑셀(`근골격계도수치료 처방 명단` 시트), 실제 주간 시간표는 Notion으로 분리되어 있어 이중 관리가 발생한다.
- 환자 상태(대기중 → 예약완료 → 시행중 → 종결)와 회차, 종결평가 일정을 셀 안 텍스트로 적어 누락·오류가 잦다.
- 여러 치료사가 각자 다른 파일/기기에서 수정하여 충돌이 생긴다.

**목표:** 대기자 등록부터 예약 배정, 회차 진행, 종결, 통계까지 한 화면에서 처리하고,
여러 기기에서 실시간으로 같은 데이터를 보는 클라우드 기반 웹앱을 만든다.

## 2. Goals (목표)

1. 엑셀/Notion 이중 관리를 없애고 단일 데이터 소스로 통합한다.
2. 환자 상태 흐름(대기중 → 예약완료 → 시행중 → 종결)을 클릭/드래그로 관리한다.
3. 요일×시간대 주간 시간표 그리드에서 환자 배정을 한눈에 보고 옮길 수 있게 한다.
4. 환자별 도수 회차(예: 6회/10회)와 종결평가 예정일을 자동으로 추적·알림한다.
5. 기간별·치료사별·부위별 치료 통계를 자동 집계한다.
6. 여러 기기에서 동시에 접속해도 같은 최신 데이터를 본다.

## 3. User Stories (사용자 스토리)

- **치료사로서** 새 처방 환자를 대기자 목록에 빠르게 등록하고 싶다. 그래야 누락 없이 순서대로 예약을 잡을 수 있다.
- **치료사로서** 대기 환자를 주간 시간표의 빈 시간대로 끌어다 배정하고 싶다. 그래야 내 시간이 겹치지 않게 관리할 수 있다.
- **치료사로서** 한 환자의 회차를 한 번 클릭으로 +1 하고 싶다. 그래야 매번 셀 텍스트를 고쳐 적지 않아도 된다.
- **치료사로서** 6회/10회 종결이 임박한 환자를 자동으로 알고 싶다. 그래야 종결평가 진료를 미리 예약할 수 있다.
- **치료사로서** 이번 달 내가 본 도수치료 건수와 부위별 분포를 보고 싶다. 그래야 통계 보고를 자동으로 만들 수 있다.
- **치료사로서** 집과 치료실 PC 어디서든 같은 화면을 보고 싶다. 그래야 어디서든 일정을 확인·수정할 수 있다.

## 4. Functional Requirements (기능 요구사항)

### 4.1 환자/대기자 관리
1. 시스템은 새 환자를 다음 필드로 등록할 수 있어야 한다: 처방일자, 등록번호, 성명, 처방코드, 환자 메모(부위/상병), 진료과, 나이, 성별, 담당치료사, 연락처, 희망요일, 희망시간, 비고.
2. 처방코드는 목록에서 선택한다: `도수치료 간단`, `도수치료 기본`, `도수치료 복잡` (각각 `외(외래)` 여부 토글 포함).
3. 환자 상태는 다음 4단계로 관리한다: **대기중 → 예약완료 → 시행중 → 종결**. 상태 변경은 한 번의 동작으로 가능해야 한다.
4. 대기자 목록은 상태/담당치료사/처방일자로 필터·정렬할 수 있어야 한다.
5. 등록번호 또는 성명으로 환자를 검색할 수 있어야 한다.
6. 마지막 연락일·연락결과를 기록할 수 있어야 한다.

### 4.2 주간 시간표 그리드
7. 시스템은 **요일(월~금) × 시간대** 그리드를 표시한다. 기본 시간대는 **40분 단위 하루 10타임**으로 한다:
   - 오전 4타임: 09:00–09:40, 09:40–10:20, 10:20–11:00, 11:00–11:40
   - 오후 6타임: 13:00–13:40, 13:40–14:20, 14:20–15:00, 15:00–15:40, 15:40–16:20, 16:20–17:00
   - 시간대 구성은 설정에서 바꿀 수 있어야 한다.
8. 그리드의 각 셀에는 배정된 환자(성명 + 등록번호 + 회차 요약)가 표시된다.
9. 대기/예약 환자를 그리드의 빈 시간대로 **드래그앤드롭** 하여 배정하면 상태가 `예약완료`(또는 `시행중`)로 바뀐다.
10. 배정된 환자를 다른 시간대로 드래그하여 일정을 옮길 수 있어야 한다.
11. 시간표는 **담당치료사별로 보기**를 전환하거나 전체를 함께 볼 수 있어야 한다 (치료사: 최수홍, 김대현, 김예지 등, 목록은 편집 가능).
12. "스케줄 고정" 표시가 가능해야 한다(매주 같은 시간 반복 환자).

### 4.3 회차 / 진행 추적
13. 환자별로 도수 회차 카운트를 기록한다(예: 6회차/10회). 한 번의 클릭으로 회차를 증가시킬 수 있어야 한다.
14. 각 치료 회차에 실시 날짜가 기록된다.
15. 종결 목표 회차(**기본 6회**, 환자별로 변경 가능)에 도달하면 **종결평가 예정 알림**을 표시한다.
16. 종결평가 예정일을 환자별로 지정·표시할 수 있어야 한다.
17. 상태가 `종결`이 되면 종결일이 자동 기록된다.

### 4.4 통계 / 리포트
18. 시스템은 선택한 기간(월/분기/연)에 대해 도수치료 총 건수를 집계한다.
19. 처방코드별(간단/기본/복잡), 부위별, 담당치료사별 건수를 집계해 표로 보여준다.
20. 집계 결과를 CSV(또는 엑셀)로 내보낼 수 있어야 한다.

### 4.5 데이터 / 동기화
21. 데이터는 클라우드 데이터베이스에 저장되어 여러 기기에서 같은 데이터를 본다.
22. 기존 엑셀 `근골격계도수치료 처방 명단` 시트를 **1회 임포트**하여 초기 데이터를 채울 수 있어야 한다.
23. 한 기기에서의 변경이 다른 기기에 반영되어야 한다. **실시간 동기화는 필요 없으며, 새로고침/재진입 시 최신 데이터를 보면 충분하다.**

### 4.6 로그인
24. 접근은 **공용 1개 계정(단일 비밀번호)** 으로 보호한다. 치료사별 개인 계정·권한 구분은 하지 않는다.

## 5. Non-Goals (범위 밖)

- 림프부종 도수치료(`도수치료C 스케쥴`, ICG, U/E·L/E)는 이번 범위에 포함하지 않는다 (MSK 전용).
- 병원 EMR/처방 시스템과의 실시간 연동은 하지 않는다 (수동 입력/엑셀 임포트).
- 환자에게 직접 노출되는 예약 포털·SMS 자동발송은 하지 않는다.
- 청구/수가 계산, 보험 처리는 하지 않는다.
- 복잡한 권한·결재 시스템은 만들지 않는다(소수 치료사 사용).

## 6. Design Considerations (디자인 고려사항)

- 주 화면은 **주간 시간표 그리드**, 보조 패널로 **대기자 목록**(드래그 소스)을 둔다.
- 상태는 색상으로 구분(대기중/예약완료/시행중/종결).
- 한글 입력·표시 최적화, 데스크톱 우선(치료실 PC), 태블릿에서도 열람 가능.
- 셀 안 텍스트가 길어지지 않도록 환자 카드(이름·회차·부위 요약)로 표시하고, 클릭 시 상세 패널을 연다.

## 7. Technical Considerations (기술 고려사항)

- **스택: Django 5.2 + SQLite + Docker 자체배포** (기존 `spineview` 프로젝트와 동일 패턴, 운영 노하우 재사용).
- **멀티기기 공유 방식:** 단일 서버(Docker 컨테이너 1개)가 `db.sqlite3` 하나를 영구 볼륨에 마운트해 보유. 모든 치료사 기기가 그 서버에 접속 → 같은 데이터 공유. 별도 클라우드 DB(Supabase/Turso) 불필요.
- **확장:** `dj-database-url`로 `DATABASE_URL`만 바꾸면 추후 Postgres 전환 가능(소수 사용자라 당분간 SQLite로 충분).
- **클라우드 배포(선택):** Railway/Render/Fly 등 Docker·영구디스크 지원 호스트면 가능. **Vercel은 비대상**(서버리스 파일시스템이 일시적이라 SQLite 쓰기 불가).
- 드래그앤드롭 그리드는 Django 템플릿 + **SortableJS**(또는 HTMX)로 구현.
- 엑셀 임포트는 **openpyxl**(spineview에서도 사용) 사용.
- 접근 보호는 **공용 1계정(단일 비밀번호)** 으로 충분. 개인 계정·권한 분리 없음.
- 실시간 구독은 불필요. 페이지 진입/새로고침 시 DB에서 최신 데이터를 읽는 방식이면 충분.
- 데이터 모델 핵심 엔터티(Django 모델): `Patient`(환자/처방 단위), `Appointment`(시간표 배정), `Session`(회차 실시 기록), `Therapist`(치료사), `Settings`(시간대 구성).

## 8. Success Metrics (성공 지표)

1. 엑셀/Notion 이중 입력이 사라진다(단일 소스 사용률 100%).
2. 환자 상태 변경·회차 기록이 클릭 1~2회로 완료된다.
3. 종결 임박 환자 누락이 0건이 된다(알림 기반).
4. 월간 통계 보고서 작성 시간이 수작업 대비 80% 이상 단축된다.
5. 두 대 이상의 기기에서 동일 데이터로 동시 사용한다.

## 10. v2 UI 개선 (운영 피드백 반영, 2026-06)

운영 시작 후 도수치료사 피드백을 반영한 화면 정교화. 기존 데이터/기능은 유지하고 입력·배치 UX를 단순화한다.

### 10.1 주간 시간표
- **(FR25) 전체 보기 기본화:** 첫 화면은 모든 치료사 스케줄을 한 번에 본다. 상단 탭은 `전체 | 치료사…` 구성이며 `전체`가 기본. 전체 보기는 **요일×치료사**로 열을 펼쳐 표시하고, 각 칸은 해당 치료사·요일·시간대에 직접 drag&drop 배정된다.
- **(FR26) 대기자 대기일수:** 우측 대기자 패널에 환자별 **대기일수**(처방일자 기준, 없으면 등록일)를 표기하고 **오래 기다린 순**으로 정렬한다.
- **(FR27) 예약 대기칸:** 주간 시간표가 가득 찬 상황을 위해, **요일(월~금)×오전/오후 = 10칸**의 예약 대기열을 둔다. 각 칸에 "그 시간대에 자리가 나면 다음으로 시작할 환자"를 순번대로 쌓아둔다(치료사 무관). 대기자를 칸에 끌어다 놓으면 상태가 `예약완료`가 된다.

### 10.2 환자 등록 간략화
- **(FR28) 부위/단계 분류:** 처방코드는 단일화되어 등록 시 선택하지 않는다. 대신 **부위/단계 8분류**에서 고른다: `Lumbar phase1/2/3`, `Cervical`, `Shoulder phase1/2/3`, `기타`. `기타`는 자유 입력.
- **(FR29) 입력 항목 축소:** 등록 폼에서 **외래(외) 체크박스, 진료과, 담당치료사, 상태**를 제거한다.
  - 담당치료사는 입력하지 않고 **주간 시간표에서 drag&drop**으로 배정한다(배정 시 환자에 치료사가 기록됨).
  - 상태 기본값은 `대기중`. 예약 대기칸에 넣으면 `예약완료`, **시간표 칸에 배정하면 `시행중`**으로 자동 전환된다(대기중→시간표 직접 배정도 허용).

### 10.3 상태 흐름(개정)
`대기중` → (예약 대기칸) `예약완료` → (시간표 배정) `시행중` → `종결`.
시간표에 바로 배정하면 `대기중/예약완료` → `시행중`으로 한 번에 전환된다.

## 9. Resolved Decisions (확정 사항)

1. **시간표 구성:** 40분 단위 하루 10타임 — 오전 09:00~11:40(4타임), 오후 13:00~17:00(6타임). 설정에서 변경 가능. *(FR7)*
2. **종결 기준 회차:** 기본 6회, 환자별로 변경 가능. *(FR15)*
3. **로그인:** 공용 1계정(단일 비밀번호). 개인 계정/권한 분리 없음. *(FR24)*
4. **통계 기준:** 별도 표준 양식 없음 — 기간별·처방코드별·부위별·치료사별 기본 집계 제공. *(FR18~20)*
5. **동기화:** 실시간 불필요. 새로고침/재진입 시 최신 데이터면 충분. *(FR23)*
6. **스택/배포:** Django + SQLite + Docker 자체배포(spineview와 동일). Vercel 비대상, 필요 시 Railway/Render/Fly로 Docker 배포. *(7장)*
